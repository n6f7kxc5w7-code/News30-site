# Automated pipeline — setup Turns News30 from "the feed is whatever NewsAPI returned this second" into "the feed is nine curated stories we have made videos for." ``` Vercel Cron (3×/day) ↓ /api/cron/ingest fetch 40 headlines per category, rank by significance, write top 3 per category to published_stories as pending ↓ /api/cron/process take ONE pending story → script → narration → render → thumbnail → mark ready → call itself for the next ↓ website reads published_stories where status = 'ready' ``` --- ## Step 1 — Database Run `published-stories-table.sql` in Supabase → SQL editor. Then add the thumbnail column to the existing render ledger: ```sql alter table video_jobs add column if not exists thumbnail_url text; ``` ## Step 2 — Environment variable Vercel → Settings → Environment Variables. Add: ``` CRON_SECRET = ``` Generate one however you like — 40+ random characters. This is what stops anyone triggering a full render cycle by visiting the URL, and what lets the worker bypass its own rate limits. Treat it like any other secret: no `VITE_` prefix, never in client code. ## Step 3 — Files **New:** - `api/cron/ingest.js` — paste `ingest.js` - `api/cron/process.js` — paste `process.js` **Replace:** - `api/_rate-limit.js` — now honours the internal bypass - `api/generate-video.js` — now produces a thumbnail - `vercel.json` — cron schedule and function timeouts If your existing `vercel.json` has settings beyond `functions`, merge rather than overwrite: keep what is there and add the `crons` block. ## Step 4 — Deploy, then test manually before trusting the schedule Trigger ingest by hand first. From a terminal, or any HTTP client: ``` curl -X POST https://news30.live/api/cron/ingest \ -H "Authorization: Bearer YOUR_CRON_SECRET" ``` Then watch two places: - **Supabase → Table Editor → published_stories.** Nine rows should appear as `pending`, then move through `generating` to `ready` one at a time. - **Vercel → Logs.** `[ingest]` lines show what was picked and why; `[process]` lines show each render. Expect the full queue to take several minutes — each render is a real FFmpeg job. --- ## Step 5 — Front end The app currently builds its feed from NewsAPI directly. It needs to read finished stories instead. Add this service near `newsService` in `App.jsx`: ```js /* 🔌 PUBLISHED STORIES — the real feed.
